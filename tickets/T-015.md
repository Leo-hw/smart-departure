## 배경

- 새로 발급한 `GOOGLE_MAPS_API_KEY`는 Routes API용이라, 기존 코드가 호출하던 Directions API(Legacy)
  `maps/api/directions/json`에서는 실패한다.
- 실패하면 이동 시간을 30분으로 추정해 알림에 "(이동 시간 추정)"이 붙는다.

## Acceptance Criteria

- [x] `_GoogleMapsProvider`가 `POST https://routes.googleapis.com/directions/v2:computeRoutes`를 호출
  (`X-Goog-Api-Key`, `X-Goog-FieldMask: routes.duration`, 키는 URL에 넣지 않음)
- [x] 이동 수단 매핑: transit→TRANSIT, walking→WALK, driving→DRIVE(실제로는 카카오가 처리), 그 밖→TRANSIT
- [x] 응답 `routes[0].duration`("2100s")을 분으로 변환. 빈 응답·형식 오류·HTTP 오류는 기존처럼 캐시 → 30분 추정
- [x] 공개 함수 `get_travel_time()`와 `TravelResult`, 캐시·카카오 경로는 그대로
- [x] 단위 테스트 갱신·추가(50개 통과)
- [x] begonia 폰에서 실제 키로 확인 (2026-11-13): provider 직접 호출로 집→서울역/강남역/판교역 28/47/57분, 추정값 아님. 이후 실제 일정에서 `estimated=False` 확인(인계서 참조)

## 추가 평가 (2026-11-13): 카카오맵 대중교통 경로 조회로 바꿀 수 있나

> 결정 전 시험만 함. 코드는 아직 구글 Routes API 그대로.

- 카카오맵 REST API(`GET https://dapi.kakao.com/v2/routing/publictraffic`, `Authorization: KakaoAK {REST 키}`)에
  대중교통 경로 조회가 일반 REST 키로 제공됨(2026-07 카카오맵 API 개편). 제휴가 필요한 카카오모빌리티 대중교통 API와는 다른 제품.
- 무료 쿼터: 대중교통 하루 1,000건(초과 시 429, 유료 건당 10원). 콘솔 [카카오맵] 사용 설정 ON 필요. 출발 시각 지정 파라미터는 없음(현재 시각 기준).
- 입력은 좌표(x=경도, y=위도) → 기존 카카오 주소 검색(`/v2/local/search/address.json`, 실패 시 `keyword.json`)으로 변환.
- 응답: `status`, `routes[]`(15개), `routes[].properties` = `totalTime`(초), `totalDistance`, `fare`, `transfers`, `type`(BUS·SUBWAY·BUS_AND_SUBWAY).

| 집 → | Google Routes | Kakao 첫 경로 | Kakao 최단 |
|---|---|---|---|
| 서울역 | 28분 | 29분 | 29분 |
| 강남역 | 47분 | 48분 | 47분 |
| 판교역 | 57분 | 60분 | 55분 |

- 응답 속도는 둘 다 0.3–0.5초. 소요 시간 차이 1–3분.
- 카카오 첫 경로가 항상 최단은 아님(판교 60분 vs 최단 55분) → 바꾼다면 `min(totalTime)` 또는 첫 경로(추천) 중 기준을 정해야 함. 출발 알림은 늦지 않는 게 중요하므로 첫 경로(추천)나 보수적인 쪽을 권장.

**제안 (미결정)**: 대중교통 provider를 카카오로 바꾸고 구글은 실패 시 예비로 두면 키 하나(카카오)로도 동작하고 구글 결제 계정 의존이 없어진다.
바꿀 경우 별도 티켓(T-016)으로: `_KakaoTransitProvider` 추가, `settings.yaml` `transport.transit.api: "kakao"` 반영, `GOOGLE_MAPS_API_KEY` 필수 해제.

## 함께 발견한 문제 (보고만, 수정 안 함)

- `GOOGLE_CALENDAR_IDS` 중 하나라도 접근 불가(404 notFound — 서비스 계정에 공유 안 됨/잘못된 ID)면
  실행 전체가 `startup failed: HttpError`로 종료(exit 1)된다. 접근 가능한 나머지 캘린더 알림도 나가지 않음.
  → 캘린더별로 실패를 건너뛰고 경고만 남기는 편이 안전(별도 티켓 후보).
