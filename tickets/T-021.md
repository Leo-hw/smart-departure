# T-021 — 출발 알림 시각·경로 안내 문구 정합성

**상태**: ⚪ TODO
**담당**: Codex
**의존**: T-018, T-020

## 배경

2026-11-20 운영 테스트에서 19:30 일정의 출발 예정은 18:53이었지만, `alert_window_minutes: 15` 설정에 따라 18:40 알림이 `🚀 출발할 시간이에요!`로 발송됐다. 같은 알림에는 `이동 시간 추정`과 현재 조회 경로의 18:45 탑승 시각이 함께 표시됐다. 18:40에 조회한 경로의 탑승 시각을 18:53 출발 예정과 나란히 제시하면 그 차를 탈 수 있다고 오해하기 쉽다.

`이동 시간 추정`은 API 실패·캐시/추정 fallback뿐 아니라, T-018의 보수적 최대 이동 시간(이전 정상 조회값)을 유지하면서 현재 API 값이 더 짧은 경우에도 붙는다. 정상 API 응답을 실패나 단순 추정으로 오인하게 해서는 안 된다.

## Acceptance Criteria

- [ ] 출발 예정 시각보다 이른 알림은 `출발할 시간`이라고 단정하지 않고, 남은 시간과 예정 시각을 명확히 표시한다. 예정 시각 이후 알림은 기존 지각/catch-up 표시와 모순되지 않는다.
- [ ] `on_time` 판정에 사용하는 15분 윈도우와 실제 발송 시각의 의미를 분리한다. 조기 발송 정책을 유지하거나 변경할 때 5분 타이머 지연·중복 발송 방지에 미치는 영향을 검증한다.
- [ ] 정상 API 조회값보다 보수적 이동 시간을 유지한 경우와 API 실패·캐시·기본 추정 fallback을 서로 다른 문구로 설명한다. 알림의 이동 시간과 경로 단계가 서로 다른 기준일 수 있음을 숨기지 않는다.
- [ ] 알림에 표시하는 탑승 시각이 안내된 출발 예정 시각보다 빠를 때, 그 경로를 출발 예정 시각에 탈 수 있는 것처럼 제시하지 않는다. 조회 시점 경로임을 명확히 하거나 부적절한 탑승 시각을 생략한다.
- [ ] 준비/출발 알림, API 정상·fallback, 이동 시간 증가·감소, 조기·정시·지각, dedup에 대한 단위/회귀 테스트를 추가한다. 실제 운영 검증에서는 일정명·주소·키를 로그나 공개 문서에 남기지 않는다.
