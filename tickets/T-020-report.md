## 원래 기획과 달라진 점

- 별도의 경로 변경 알림은 만들지 않았다. 기존 준비/출발 알림에서 새로 조회한 경로만 보여줘 알림 폭주를 피한다. 준비 알림에서는 현재 조회 경로의 탑승 시각을 표시하지 않는다.
- [Google Routes 정책](https://developers.google.com/maps/documentation/routes/policies)의 캐시·출처 요건을 고려해 단계 데이터는 메모리에서만 사용하고 알림에는 `Google Maps`를 표기한다.

## 발생한 에러/이슈

- 기존 테스트 1개는 요청 field mask 추가로 기대값을 갱신했다.
- 실제 한국 경로의 단계 필드 품질은 라이브 API로 아직 검증하지 않았다. 모의 응답 및 기존 생산 타이머의 코드 경로는 검증했다.

## 다음 작업자에게 전달할 주의사항

- 다른 제공자는 공통 `RouteGuide`를 반환하도록 어댑터를 구현한다. 알림/스케줄러에 제공자별 JSON 필드를 넣지 않는다.
- 출발 시각은 T-018 정책에 따라 보수적으로 유지될 수 있지만, 경로 단계는 현재 API 응답 기준이다. 둘을 동일한 이동 시간 기준이라고 표시하지 않는다.
- 운영 검증 시 개인 일정명·주소·API 키를 로그나 공개 문서에 남기지 않는다.
