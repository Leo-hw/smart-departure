# T-019 리포트 — 캘린더별 접근 실패 격리

## AC 결과

- ✅ 개별 캘린더의 404 및 접근권한 403은 경고를 남기고 다음 캘린더를 조회한다.
- ✅ 접근 가능한 캘린더가 하나도 없으면 `RuntimeError`로 실패한다. 접근 가능한 빈 캘린더는 정상 조회로 센다.
- ✅ 401 인증 실패, 구조화된 403 인증·설정·할당량 오류, 429/5xx, 네트워크 예외는 즉시 전파해 실패로 처리한다.
- ✅ 경고에는 캘린더 순번과 상태 코드만 출력한다. ID·일정·주소·자격 증명·응답 본문은 출력하지 않는다.
- ✅ 전체 단위 테스트 63개, `py_compile`, `git diff --check` 통과. Maps fallback과 dedup 회귀 테스트도 통과.

## 기획 대비 변경

- HTTP 403은 모두 무조건 건너뛰지 않는다. API가 반환한 구조화된 사유가 인증·할당량·API 설정 문제로 알려진 경우 전체 실패로 분류한다. 그 외 403은 캘린더별 접근 실패로 처리한다.

## 이슈 및 인계

- 실제 서비스 계정으로 접근 불가능한 캘린더를 추가하는 운영 검증은 수행하지 않았다. 다음 배포 후 필요 시 임시 캘린더 ID로 경고와 다른 일정의 정상 처리 여부를 확인한다.
- HTTP 오류 본문은 내부 분류에만 사용하며 로그에 쓰지 않는다. 새 Google 오류 사유가 나오면 `GLOBAL_403_REASONS` 분류를 갱신해야 할 수 있다.
