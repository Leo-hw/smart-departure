## 원래 기획과 달라진 점

- 조기 발송을 없애지 않고 메시지 표현만 바꿨다. 5분 폰 타이머의 실행 지연에 대비한 기존 15분 판정 윈도우를 유지한다.
- `is_estimated`는 API fallback 여부만 나타내도록 분리했다. 보수적 계획값은 `current_travel_minutes`와 비교해 표시한다.

## 발생한 에러/이슈

- 회귀 테스트 작성 중 준비 단계 catch-up도 조기 출발 시각에 후보로 나올 수 있음을 확인했다. 출발 dedup 검사는 출발 후보만 분리해 검증했다.
- 폰 자동 pull 결과 `3d38b29`가 반영됐고 타이머 활성·최근 서비스 실행 성공을 확인했다. 실제 새 문구의 디스코드 수신은 아직 확인하지 않았다.

## 다음 작업자에게 전달할 주의사항

- 현재 경로 단계는 API 조회 시점 기준이고, 계획 이동 시간은 과거 정상 조회값 중 최대값일 수 있다. 둘이 같은 여정을 보장하지 않는다는 문구를 유지한다.
- 경로 상세는 여전히 스냅샷에 저장하지 않는다. 일정명·주소·키를 운영 로그나 공개 문서에 남기지 않는다.
